# Three.js 場景實作規格

## 1. 實作基準

- `1 Three.js unit = 1 meter`
- 角色高度基準：`1.8 m`
- Three.js 座標：X 向右、Y 向上、Z 朝入口
- 原點：房間地面中心
- 室內 bounds：X `-1.8–1.8`、Y `0–2.7`、Z `-1.5–1.5`
- 後牆／窗戶：Z `-1.5`
- 入口牆：Z `+1.5`

`SCENE_ANALYSIS.md` 中的公分尺寸只在整理設定時轉換一次。程式內所有尺寸都直接以公尺表示。

## 2. 場景範圍與主要區域

這是單一室內書房，不包含道路、戶外地形或多棟建築：

| 區域 | 實作 |
| --- | --- |
| 入口／動線 | 前牆偏左的 0.8 m 門洞、固定開啟門扇與小型入口平台 |
| 中央工作區 | 1.2 × 0.6 × 0.75 m 書桌、入口側辦公椅、筆電與工作燈 |
| 左側收納 | 0.8 × 0.3 × 2.0 m 高書櫃與 instanced books |
| 右側收納 | 1.2 × 0.4 × 0.75 m 矮櫃、相框、盆栽與壁畫 |
| 後方採光 | 中央窗、捲簾、程序化窗外樹景與主日光 |
| 玩家活動區 | 房間地面、門洞與入口小平台；大型家具為障礙物 |

室內沒有道路。`Terrain.ts` 在本專案代表可行走地面與入口平台，而不是戶外 height field。

## 3. 主要配置

| 物件 | 尺寸（m） | 世界位置（底部中心或設定基準） |
| --- | --- | --- |
| 房間 | 3.6 W × 3.0 D × 2.7 H | 原點置中 |
| 書桌 | 1.2 W × 0.6 D × 0.75 H | `[0, 0, -0.32]` |
| 辦公椅 | 約 0.6 W × 0.6 D × 1.1 H | `[0, 0, 0.46]`，面向窗戶 |
| 書櫃 | 0.8 W × 0.3 D × 2.0 H | `[-1.64, 0, -0.92]`，沿左牆旋轉 90° |
| 收納櫃 | 1.2 W × 0.4 D × 0.75 H | `[1.58, 0, 0.18]`，沿右牆旋轉 -90° |
| 窗戶 | 1.4 W × 1.28 H | 窗台高 0.88，後牆置中 |
| 門 | 0.8 W × 2.08 H | 中心 X `-1.31`，固定向左牆開啟 |
| 玩家 | 1.8 H、半徑 0.22 | 起點 `[0.83, 0, 1.05]` |

書桌置中時，左側理論通道約 0.9 m，右側約 0.8 m。玩家直徑 0.44 m，可沿兩側通過；書桌、椅子與矮櫃之間仍刻意保持小房間的緊湊感。

## 4. 前景、中景與背景

- 前景：左側開門、門把、地板、辦公椅腳輪。
- 中景：辦公椅、書桌、筆電、工作燈、矮櫃與桌面植栽。
- 背景：中央窗戶、捲簾、窗外綠景、壁畫；書櫃由中景延伸至背景。
- 上方背景：天花板與圓形吸頂燈。

參考相機位於 `[-0.3, 1.46, 3.15]`、視線朝中央工作區；它會隱藏前牆的 cutaway pieces，但不移除碰撞，也保留開啟門扇，讓左前景與中央軸的比例接近原始主透視。

## 5. 基本幾何與 GLB 邊界

| 類型 | 目前做法 | 後續方向 |
| --- | --- | --- |
| 房殼、門窗、踢腳板、捲簾 | Box／Cylinder 基本幾何 | 維持程序化 |
| 地板 | 交錯的 InstancedMesh 木板 | 可改貼圖，但不必逐片高模 |
| 書桌、書櫃、收納櫃 | 共用板件與方管 | 維持模組化 |
| 書籍、盆器、葉簇、窗外樹 | Seeded InstancedMesh | 增加變體而非單件複製 |
| 辦公椅 | 程序化 fallback | 最適合替換 GLB |
| 工作燈 | 程序化 fallback，保留清楚關節輪廓 | 可替換 GLB |
| 筆電 | 程序化 fallback | 近距互動時換 GLB |
| 書櫃頂垂吊植物 | 程序化 fallback | 英雄鏡頭可換 GLB |

所有 GLB 透過 `AssetManager` 載入；manifest 的 `scale`／`offset` 套用在模型局部座標，外層 wrapper 再套用 `sceneConfig` 的世界位置。碰撞永遠使用集中設定的簡化代理，不從模型三角形自動生成。

## 6. 無法確認與合理補完

- 椅子採主透視圖：位於書桌入口側，而不是俯視圖中的窗側。
- 書櫃採尺寸卡 `0.8 × 0.3 × 2.0 m`，不採俯視圖看似接近 2 m 的沿牆長度。
- 門使用 0.8 × 2.08 m，窗使用 1.4 × 1.28 m，皆位於分析文件的合理估算範圍。
- 門固定完全開啟；尚不推測門鉸鏈動畫、鎖舌或互動規則。
- 窗外只建立低面數樹景，沒有擴充未出現在設計圖中的完整戶外世界。
- 電線、插座及不可辨識的小道具不加入主要碰撞。
- 光照假設為柔和日間窗光加低強度吸頂燈。

## 7. 模組與資料流

```text
sceneConfig
   ├─ SceneSystem ─ Terrain / Buildings / Furniture / Props / Vegetation / Lighting
   ├─ CollisionSystem ─ static AABB + walkable boxes
   ├─ CameraSystem ─ reference / player / free
   ├─ ControlsSystem ─ input + fixed-step movement + gravity
   ├─ AssetManager ─ lazy GLB loader + cache + fallback
   └─ DebugSystem ─ renderer.info + collider helpers + 1.8m scale
```

`RoomApp` 以固定 60 Hz 更新玩家物理，再更新相機、渲染場景，最後以 4 Hz 更新 DOM HUD。動畫迴圈不建立新的 Vector3、Box3 或道具。
